编译 AOSP 总流程 ​

记录为 Pixel 3（blueline）搭建 AOSP 编译环境的全过程，运行环境为 Debian 13，已写步骤均经实机验证。

配置 SSH 免密登录 ​

后续步骤均在该主机上执行，先配置免密登录。

项目值
系统Debian 13
IP192.168.2.13
用户kpa

  1. Windows 机器上生成密钥对（默认路径、空口令）：

    powershell
    ssh-keygen -t rsa

  2. Windows 机器上查看公钥：

    ps1
    PS C:\Users\Kpa\.ssh> cat .\id_rsa.pub

  3. 登录主机，将公钥写入 authorized_keys 并设置权限：

    sh
    ssh kpa@192.168.2.13
cd ~
mkdir -p .ssh && echo "上面公钥内容" > .ssh/authorized_keys
chmod 700 .ssh && chmod 600 .ssh/authorized_keys

  4. Windows 侧配置连接信息，在 C:\Users\Kpa\.ssh\config 中加入：

    Host 192.168.2.13
  HostName 192.168.2.13
  User kpa
  IdentityFile C:\Users\Kpa\.ssh\id_rsa

    查询结果：

    Build Id标记版本支持的设备安全补丁级别

    即 tag 为 android-11.0.0_r46，后续按该 tag 拉取源码。

    适用于 Android 11.0.0（RQ3A.211001.001）的 Pixel 3 二进制文件：

  3. 根据 build id 查询对应的原厂刷机包：https://developers.google.cn/android/images?hl=zh-cn

环境准备 ​

Debian 13 下安装 LXD 作为容器管理工具。

sh
# 安装 LXD（Debian 13 软件源中包名为 incus）
sudo apt update
sudo apt install -y incus

# 将当前用户加入 incus-admin 组，之后操作容器无需每次都加 sudo
sudo adduser $USER incus-admin

# 当前终端激活分组（不用重新登录），之后所有 incus 命令都不需要 sudo
newgrp incus-admin

# 初始化向导会依次询问网络与存储配置；日常本地开发一路回车（全部默认值）即可
incus admin init

# 验证服务可用
incus list

配置 Git ​

在宿主机上配置 git 提交身份与镜像重定向：

sh
git config --global user.email "473926009@qq.com"
git config --global user.name "kpa"

# 将 android.googlesource.com 重定向到科大镜像，后续 repo 拉取自动走镜像
git config --global url."https://mirrors.ustc.edu.cn/aosp/".insteadOf "https://android.googlesource.com/"

下载 Repo 工具 ​

在宿主机上执行：

sh
sudo apt install repo -y
# 安装好后执行 repo -h 检查

再通过科大代理获取官方脚本，并将 repo 自我更新源持久指向国内镜像：

sh
mkdir -p ~/bin
PATH=~/bin:$PATH

# 下载 repo 脚本（清华镜像，连接更稳）
curl https://mirrors.tuna.tsinghua.edu.cn/git/git-repo > ~/bin/repo
chmod a+x ~/bin/repo

# 关键：指定 repo 自我更新的国内镜像源
export REPO_URL='https://gerrit-googlesource.proxy.ustclug.org/git-repo'

# 建议把上面两项永久写入 ~/.bashrc
echo 'export PATH=~/bin:$PATH' >> ~/.bashrc
echo "export REPO_URL='https://gerrit-googlesource.proxy.ustclug.org/git-repo'" >> ~/.bashrc

拉取 AOSP 源码 ​

在宿主机上按 tag android-11.0.0_r46 初始化仓库，--depth=1 浅克隆：

sh
mkdir aosp && cd aosp
repo init -u https://mirrors.ustc.edu.cn/aosp/platform/manifest -b android-11.0.0_r46 --depth=1
# 同步代码
repo sync -c -j4

创建 aosp11 容器 ​

容器系统镜像按手机目标系统选择：目标为 Android 11，编译容器使用 Ubuntu 18.04。官方远程镜像 images:ubuntu/18.04 已因过期下架，无法再用 incus launch 直接拉取，改为手动下载官方归档并导入为本地镜像。

sh
# 1. 下载官方归档（amd64 为例）
wget https://cloud-images.ubuntu.com/releases/bionic/release/ubuntu-18.04-server-cloudimg-amd64-lxd.tar.xz
wget https://cloud-images.ubuntu.com/releases/bionic/release/ubuntu-18.04-server-cloudimg-amd64.squashfs

# 2. 导入为本地镜像
incus image import ubuntu-18.04-server-cloudimg-amd64-lxd.tar.xz ubuntu-18.04-server-cloudimg-amd64.squashfs --alias ubuntu-18.04

# 3. 启动并进入容器
incus launch ubuntu-18.04 aosp11
incus exec aosp11 -- bash

常用容器操作（容器名 aosp11）：

操作命令说明
查看状态incus list查看所有容器的运行状态、IP、资源占用
进入容器incus exec aosp11 -- bash相当于 SSH 登录进容器终端
退出终端exit退出终端回到宿主机（容器仍会继续运行）
停止容器incus stop aosp11类似于关机，下班不用时可以关掉
启动容器incus start aosp11启动已经存在的容器（不用再 launch 了）
重启容器incus restart aosp11重启容器
彻底删除incus delete -f aosp11强制删除容器（-f 表示即使在运行也强行删除）
主机/容器拷文件incus file push 本地文件 aosp11/root/将宿主机文件拷贝进容器
容器/主机拷文件incus file pull aosp11/root/文件 本地路径将容器里的文件拷回宿主机

挂载源码到容器 ​

容器只用于编译，源码放在宿主机，以 disk 设备挂载进容器：

sh
# shift=true 利用内核 idmap 机制，让容器内的 root 读写该目录时自动映射为宿主机的 kpa 权限
incus config device add aosp11 aosp_share disk source=/home/kpa/aosp path=/root/aosp shift=true

容器内源码目录即 /root/aosp，后续编译在该目录进行。

安装 AOSP 编译环境 ​

在 aosp11 容器内执行：

sh
sudo apt update
sudo apt install flex bison build-essential zlib1g-dev gcc-multilib g++-multilib libc6-dev-i386 libncurses5 lib32ncurses5-dev x11proto-core-dev libx11-dev lib32z1-dev libgl1-mesa-dev libxml2-utils xsltproc fontconfig -y
sudo apt install make git-core gnupg zip unzip curl python3 openjdk-11-jdk -y

sudo apt clean && sudo apt autoremove -y

配置内存交换空间 ​

本机器 64G 内存，无需配置交换空间；内存低于 32G 时再开启（32G 内存编译到一半进程会被 kill）：

sh
sudo swapoff /swapfile
sudo rm /swapfile
sudo fallocate -l 32G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile

# 配置永久交换
# /etc/fstab
# 最后一行插入，进入后按 i 进入编辑模式，修改好按 ESC :wq
sudo apt-get install vim
sudo vim /etc/fstab
/swapfile swap swap defaults 0 0

# 配置交换规则
# /etc/sysctl.conf
sudo vim /etc/sysctl.conf
vm.min_free_kbytes=1500000 # 大致 1.5G，启用交换

# 重启生效

编译 ​

在 aosp11 容器内执行，repo 命令用法参考：https://source.android.com/docs/setup/reference/repo?hl=zh-cn

sh
cd ~/aosp

# 加载 shell 环境变量，只有加载了变量后，对应的命令才可以使用
source ./build/envsetup.sh

# 选择编译哪种版本，lunch 命令输出菜单，列出当前 Android 源码支持的所有设备代号和编译类型，输入相应数字选择
lunch
# lunch 给出的列表选项都是 debug 版本，如果想要纯粹的 user 版本，直接指定运行
lunch aosp_blueline-user

# 设置编译线程，12 代表 12 个线程同时编译
make -j12

# 遇到错误后清理再重新编译
make clean

不要删除 aosp/.repo 目录，否则相当于重新下载。

编译类型说明：

  • user：限制所有权限，用于发布给用户使用的最终版本
  • userdebug：开放部分权限，允许 root
  • eng：工程师模式，开放所有权限并且有额外的调试工具

启动模拟器 ​

运行模拟器需要硬件加速（KVM），先安装并验证：

sh
# 安装 kvm
sudo apt-get install cpu-checker
sudo chmod 777 -R /dev/kvm

# 测试 kvm
egrep -c '(vmx|svm)' /proc/cpuinfo
kvm-ok

cd ~/aosp
source ./build/envsetup.sh
lunch aosp_x86_64-eng
emulator

刷机 ​

编译好之后开始刷机，以 Pixel 3 为例，依次执行：

sh
adb reboot fastboot

# 等待手机进入 fastboot 界面之后
fastboot flashall -w

# 刷机完成之后，执行 fastboot reboot 进入系统
fastboot reboot

fastboot flashall -w 在工程外面执行时，要配置 $ANDROID_PRODUCT_OUT 目录环境

单独编译 ​

在 aosp11 容器内、~/aosp 目录下：

sh
# 设置环境
source ./build/envsetup.sh
lunch aosp_x86_64-eng

# 单独编译 framework
make framework-minus-apex

# 使用 make snod 命令重新生成 system.img，运行模拟器查看
make snod

# 清数据启动
emulator -wipe-data

sh
# 创建分支
